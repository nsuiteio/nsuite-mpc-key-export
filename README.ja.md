# nsuite-mpc-key-export

[English](README.md) | 日本語

N Suite の MPC ウォレット秘密鍵を、オフラインでエクスポート・復元するための
デスクトップアプリ 2 本です。ネットワーク通信を一切行いません。

復元の成立要件である「取出用キーペアファイル」と「暗号化ウォレット秘密鍵ファイル」を
**別々の担当者が別々に保管する**運用（2-of-2 の分離保管）を前提としています。

## 2 つのアプリと役割

| アプリ | 想定利用者 | 役割 |
|---|---|---|
| KeyPairGenerator | エクスポート準備担当者（A） | 取出用キーペアの生成・ファイル保存・公開鍵の受け渡し |
| KeyRestore | エクスポート実行者（B） | 暗号化ウォレット秘密鍵ファイルとキーペアファイルからウォレット秘密鍵を復元・取り出し |

- **エクスポート準備担当者（担当者 A）**: 取出用キーペアの生成・保管。
- **エクスポート実行者（担当者 B）**: モバイルアプリでの暗号化ウォレット秘密鍵
  ファイルの作成、N Board でのダウンロード、ファイルの保管。

## ダウンロード

[Releases](https://github.com/nsuiteio/nsuite-mpc-key-export/releases) から
お使いの OS 向けのアーカイブを取得してください。

| ファイル | 対応 OS |
|---|---|
| `KeyExport-macOS.tar.gz` | macOS（universal: Apple Silicon / Intel） |
| `KeyExport-Windows.tar.gz` | Windows（x64） |

どちらのアーカイブにも **2 つのアプリが同梱**されています。展開後、自分の役割に
対応するアプリだけを使ってください。

- エクスポート準備担当者（A）→ `KeyPairGenerator`
- エクスポート実行者（B）→ `KeyRestore`

## 初回起動

v1.0.2 以降、macOS 版のアプリは Developer ID で署名され、Apple の公証を受けています。
Windows 版はコード署名を行っていないため、初回起動時に OS の警告が表示されます。
**開く前に（Windows では警告を回避する前に）、ダウンロードしたファイルを検証して
ください。** この警告は、署名が無いことが原因でも、ダウンロードの破損や改変が
原因でも同じように表示されます。本ツールは鍵素材を扱うため、両者を区別せずに
保護を解除すべきではありません。

### ダウンロードの検証

1. 必ず公式のリリースページから取得する:
   <https://github.com/nsuiteio/nsuite-mpc-key-export/releases>
2. 取得したアーカイブのチェックサムを、GitHub が公開している当該資産の digest と
   照合する。`sha256:` の接頭辞を除いて完全に一致する必要があります。

```sh
# 手元のファイル
shasum -a 256 KeyExport-macOS.tar.gz          # macOS
certutil -hashfile KeyExport-Windows.tar.gz SHA256   # Windows

# 公開されている digest
gh api repos/nsuiteio/nsuite-mpc-key-export/releases/latest \
  --jq '.assets[] | "\(.name) \(.digest)"'
```

`gh` CLI が無い場合は、同じ `digest` の値を
`https://api.github.com/repos/nsuiteio/nsuite-mpc-key-export/releases/latest`
から読み取れます。

**チェックサムが一致しない場合は、そこで中止してアプリを開かないでください。**
[SECURITY.md](SECURITY.md) の手順で報告してください。

### macOS

初回起動時に「インターネットからダウンロードされたアプリケーションです。開いても
よろしいですか?」と確認されます。「開く」を選んでください。

署名は自分でも確認できます。両アプリとも `source=Notarized Developer ID` と
double jump.tokyo のチーム ID `FS25FA38F2` が表示される必要があります。

```sh
spctl --assess --verbose=2 --type execute KeyPairGenerator.app
# KeyPairGenerator.app: accepted
# source=Notarized Developer ID
# origin=Developer ID Application: double jump.tokyo Inc. (FS25FA38F2)
```

**「壊れているため開けません」「悪質なソフトウェアかどうかを確認できません」
「開発元が未確認」と表示された場合は、そこで中止してください。** 署名・公証済みの
ビルドではこれらは表示されません。quarantine 属性の削除や右クリック→「開く」で
回避せず、[SECURITY.md](SECURITY.md) の手順で報告してください。

### Windows

SmartScreen の「WindowsによってPCが保護されました」が表示された場合、
「詳細情報」→「実行」を選びます。これもチェックサムの一致を確認してから行って
ください。

### 実行環境

本ツールはネットワーク通信を行いませんが、鍵素材を扱うため
**ネットワークから切り離した PC での実行を推奨**します。

## エクスポート全体の流れ

1. **エクスポート準備**（KeyPairGenerator）: 取出用キーペアを生成し、
   取出用公開鍵をエクスポート実行者に渡す。
2. **暗号化ウォレット秘密鍵ファイルの作成**（N Suite モバイルアプリ）:
   取出用公開鍵を入力し、署名鍵（KeyShare）を暗号化する。
3. **ダウンロード**（N Board）: 暗号化ウォレット秘密鍵ファイル（zip）を
   ダウンロードして保管する。
4. **復元・取り出し**（KeyRestore）: キーペアファイルと
   暗号化ウォレット秘密鍵ファイルからウォレット秘密鍵を復元・取り出す。

## 用語

- **取出用キーペア**: ウォレット秘密鍵の取り出しに使う RSA-2048 キーペア。
  公開鍵を N Suite モバイルアプリに渡すと、署名鍵（KeyShare）がこの公開鍵で
  暗号化される。エクスポート準備担当者がキーペアファイル（`*.nstkey`）として
  保管する。
- **暗号化ウォレット秘密鍵ファイル（zip）**: N Board からダウンロードする
  暗号化済みの署名鍵（FRONT/RECTO/VERSO の 3 パーティ分）。
  エクスポート実行者が保管する。**ダウンロード完了時点で、このファイルが
  ウォレット秘密鍵を復元できる唯一の実体**となる（再ダウンロードは不可）。
- **ウォレット秘密鍵**: 暗号化ウォレット秘密鍵ファイルとキーペアファイルの
  両方が揃ったときだけ復元できる、資産を直接操作可能な秘密鍵
  （root 鍵および HDPath 導出された子鍵）。

## KeyPairGenerator の使い方

エクスポート準備担当者（A）が、取出用キーペアを生成する手順です。

- 取出用キーペア（RSA-2048）を生成し、ユーザーが選択したファイルにのみ保存する。
  アプリ自体は何も永続化しない。
- 公開鍵を hex・QR コード・フィンガープリント（`hex(sha256(pubkeyBytes))`）で
  表示する。フィンガープリントはエクスポート実行者のモバイルアプリの表示と
  目視照合する（公開鍵すり替え対策）。
- **フィンガープリントの表示は読み上げやすい先頭 8 桁（例 `F570 C28F`）を既定と
  し、「全桁を表示」で 64 桁すべてを展開できる**。短縮値は 32bit しかないため、
  厳密な照合は必ず全桁で行う（モバイルアプリ側も同じ表示仕様）。
- 保存ダイアログの初期ファイル名は
  `nsuite-mpc-extraction-keypair-<短縮フィンガープリント>.nstkey`。
  暗号化ウォレット秘密鍵ファイル（`nsuite-mpc-export-<短縮フィンガープリント>.zip`）
  と接頭辞・フィンガープリント部を揃えているため、2 つのファイルの組み合わせを
  確認する目安になる（短縮値は 32bit で手動リネームもされ得るため、確証には
  ならない。読み込みはファイル名に依存しないので、旧名で保存済みのファイルも
  そのまま開ける）。
- 保存済みキーペアファイルを選択して公開鍵情報を再表示できる
  （2 回目以降のエクスポート用）。

### キーペアファイルを暗号化しない理由

キーペアファイルは平文（ヘッダ付き独自形式 `*.nstkey`）で保存されます。

- キーペア単体では何もできない（暗号化ウォレット秘密鍵ファイルが揃って初めて
  ウォレット秘密鍵を復元可能）。主たる統制は**別々の担当者による分離保管**である。
- 数年後に一度だけ使う災害復旧材料にとって、最大の喪失リスクは攻撃者ではなく
  「パスワード忘れ」であり、パスワード暗号化は復元の可用性を損なう。

## KeyRestore の使い方

エクスポート実行者（B）が、ウォレット秘密鍵を復元・取り出す手順です。

- キーペアファイルと暗号化ウォレット秘密鍵ファイルを選択し、3 つの署名鍵から
  root 鍵を**メモリ上でのみ**復元する。
  復元結果は一切永続化せず、終了すると消える。
- curve 種別（ECDSA=EVM / EdDSA=Solana）と HDPath index を指定して
  アドレスを導出・確認したうえで、対応する子秘密鍵を取り出す
  （MetaMask 等へのインポート用）。秘密鍵は既定でマスク表示、コピーは
  一定時間後に自動クリアする。
- **復元リハーサル**: アドレス確認まで行い、N Suite 上のウォレットアドレスと
  一致することを確認すれば、秘密鍵を表示せずに暗号化ウォレット秘密鍵ファイルの
  復元可能性を実証できる。

## 保管・運用ルール

- **キーペアファイルと暗号化ウォレット秘密鍵ファイルを同一のストレージ・
  バックアップ系統に置かない**（同じ共有ドライブ・NAS・クラウドバックアップへの
  同居が典型的な事故）。各担当者がオフラインメディア（USB 等）で保管することを
  推奨。
- 両ファイルが揃うと（キーペアが平文のため）ウォレット秘密鍵を復元できる。
- **どちらか一方だけが漏洩した場合**は、ウォレットが N Suite で稼働中であれば
  新しいキーペアで再エクスポートし、**その後に前世代のファイルを破棄する**。
  再エクスポート自体が旧ファイルを無効化するわけではない。同じウォレットの鍵素材を
  新しい取出用キーペアで暗号化し直すだけなので、旧キーペアファイルと旧暗号化
  ファイルの組み合わせは依然として成立する。守りになるのは、漏洩したファイルの
  相方がどこにも存在しなくなることである。
- **両方が漏洩した場合**は、ウォレット秘密鍵が侵害されたものとして扱う。
  ウォレットのアドレス（＝その基になる鍵）は変わらないため、再エクスポートでは
  取り消せない。資産を新しいウォレットへ移す。
- キーペアファイルの喪失は、N Suite 稼働中であれば再エクスポートで
  復旧できる。**N Suite の解約前に必ず復元リハーサル（アドレス一致確認）を
  実施する**こと。解約後はどちらのファイルを失っても復旧手段がない。

## セキュリティ上の重要な注意

**取り出した子秘密鍵は root 鍵と同等の機密として扱ってください。**

N Suite の HDPath 導出は、既存アドレスとの互換性のため非 hardened の BIP32 CKD を
使用しています。chaincode は root 公開鍵から決定的に計算されるため、root 公開鍵を
知り得る主体に子秘密鍵が 1 つでも漏洩すると、`rootScalar = childScalar - Σ IL` に
より root 秘密鍵（＝同グループの全アドレスの秘密鍵）が復元可能です。これは
N Suite のアドレス体系（MPC 署名時の delta 注入方式）に固有の性質であり、本ツール
側で hardened 導出へ変更することはできません。取り出し画面では取り出し前にこの
警告への同意を必須にしています。

## オフライン動作

本ツールは HTTP クライアント・テレメトリ・自動更新を一切持たず、完全にオフラインで
動作します。鍵素材（取出用秘密鍵・署名鍵の平文・復元結果・導出した秘密鍵）
はログに出力しません。
